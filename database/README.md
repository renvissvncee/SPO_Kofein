## База данных

Проект использует PostgreSQL.

### Структура базы данных

База данных состоит из следующих основных сущностей:

| Таблица | Назначение |
|---|---|
| `users` | Пользователи системы |
| `coffee_shops` | Кофейни |
| `coffee_shop_owners` | Связь пользователей с кофейнями |
| `menu_categories` | Категории меню |
| `menu_items` | Позиции меню |
| `orders` | Заказы пользователей |
| `order_items` | Позиции заказов |
| `favorites` | Избранные кофейни пользователей |

Схема совпадает с ORM-моделями бэкенда (`backend/db/models.py`).

### Особенности

- Владельцы кофейни хранятся только в `coffee_shop_owners`; поле `owners` в ответе API собирается из этой таблицы.
- `coffee_shops.coffee_shop_image` — ссылка на обложку кофейни.
- Статусы заказа (`orders.status`), по умолчанию `pending`:

  | Статус | Значение |
  |---|---|
  | `cart` | Корзина, заказ ещё не оформлен |
  | `pending` | Оформлен, ждёт подтверждения кофейни |
  | `confirmed` | Кофейня приняла заказ и готовит |
  | `ready` | Готов, можно забирать |
  | `completed` | Выдан |
  | `cancelled` | Отменён |

### Связи между таблицами

- `users` → `orders` — один пользователь может иметь несколько заказов.
- `users` ↔ `coffee_shops` — связь многие-ко-многим через `coffee_shop_owners`.
- `coffee_shops` → `menu_categories` — одна кофейня содержит несколько категорий меню.
- `menu_categories` → `menu_items` — одна категория содержит несколько позиций меню.
- `coffee_shops` → `menu_items` — позиции меню принадлежат кофейне.
- `coffee_shops` → `orders` — у кофейни может быть несколько заказов.
- `orders` → `order_items` — один заказ содержит несколько позиций.
- `menu_items` → `order_items` — одна позиция меню может входить в несколько заказов.
- `users` ↔ `coffee_shops` — избранное, связь многие-ко-многим через `favorites` (пара пользователь–кофейня уникальна).

### Ограничения

В базе данных используются:

- первичные ключи (`PRIMARY KEY`);
- внешние ключи (`FOREIGN KEY`);
- обязательные поля (`NOT NULL`);
- уникальность категорий внутри кофейни и записей в избранном (`UNIQUE`);
- проверки числовых значений (`CHECK`);
- проверка допустимых статусов заказа (`CHECK`);
- каскадное удаление связанных записей (`ON DELETE CASCADE`).

### SQL-скрипты

- `database/schema.sql` — создание структуры базы данных.
- `database/seed.sql` — добавление начальных тестовых данных.
- `database/migration_merge.sql` — приведение уже существующей БД бэкенда к этой схеме (владельцы переносятся из старого столбца `owners` в `coffee_shop_owners`, статус `new` становится `pending`; скрипт можно запускать повторно).
